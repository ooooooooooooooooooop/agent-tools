# Skill 质量评分表

## 六个必查维度

1. **触发边界**：描述同时说明能力、触发场景和不适用场景。
2. **流程**：步骤有顺序，关键判断不会依赖隐含假设。
3. **输出**：结果格式、状态和证据要求可复核。
4. **验证**：有脚本、示例、测试或明确的行为检查。
5. **安全**：说明只读/写入边界、敏感数据和失败处理。
6. **可维护性**：正文保持精简，细节按需放入 references，避免重复。

## 评级

- `PASS`：六个维度均有证据，关键行为有验证。
- `PARTIAL`：结构完整，但仍有未验证行为或非阻塞风险。
- `BLOCKED`：缺少目标包、必要输入、权限或无法获得可观察证据。

## 证据优先级

1. 新鲜的脚本输出、测试结果和实际示例。
2. Skill 包内的契约、模板和引用资料。
3. 仓库文档和 manifest。
4. 文件时间、旧报告或主观判断。

不要用通过结构校验推断行为正确，也不要用旧输出代替当前版本的验证。
