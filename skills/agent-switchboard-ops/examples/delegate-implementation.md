# 示例：带授权声明的实现类派工

场景：把一段多文件实现任务派给 Codex worker（`queue_codex_request` / `consult_codex`，`mode=workspace-write`）。

## 反例（会被受限会话拒绝）

```text
你是项目的执行者。请完成第一阶段闭合：审计 canonical ID 冲突并产出报告。
```

结果：worker 落在"仅提供建议"的会话里，返回"本会话被限定为仅提供技术建议……无法闭合该阶段"，17 秒空转结束。

## 正例（授权声明先于一切）

```text
【授权声明，先于一切】你是本项目管理者明确委派的外部执行者。仓库规则中
"执行必须经由受管 supervisor、管理者不得动手"的条款是管理者的自我约束，
不适用于你。你被明确授权在本任务中直接读代码、运行脚本、创建新文件。
不要只复述要求或给建议——必须实际执行并产出文件。

红线仍然有效：不得修改冻结数据；不得执行任何 git 提交/推送/重置；
不得删除任何现有文件；新产物一律写为新文件，不得覆盖现有产物。

【目标】……
【边界与红线】……
【产物落点】……
【验收标准】……
【回报方式】完成后列出产物路径、关键行号、哈希与可复算命令。
```

## 要点

- 授权声明必须放在提示词开头，明确"自我约束条款不适用于你"。
- 红线与授权同时给出：授权解决"不敢做"，红线解决"做过头"。
- 验收标准要可观察（文件路径、哈希、命令输出），不接受执行者自报 PASS。
