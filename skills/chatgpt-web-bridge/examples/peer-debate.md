# 示例：对等协作模式（PEER）

任务：本地模型与网页端共同评审一个交易规则设计，双方互有盲区。

```
# 触发：用户手动发起「对等模式」
conv = "<专线 conversation_id>"

# R0 盲答：两边独立，互不锚定
# 本地：自己先写评审（存在本地，不发给对方）
# 网页端：
chat_completion(conversation_id=conv, message=(
  "[PEER R0] 独立评审以下规则设计（不看我的答案，先交你的）：\n"
  "<规则文本>\n"
  "交卷后我会发我的版本，逐条对比。"
))

# R1+ 逐条交锋（信封格式见 SKILL.md）
chat_completion(conversation_id=conv, message=(
  "[PEER R1] 规则v4\n"
  "我的立场: 11:30冻结应含未涨停主动层\n"
  "依据: 昨日回测显示…\n"
  "对你上轮的反驳: 你的最强版本是『涨停簇已代表线强度』，但…\n"
  "我可能盲的地方: 你的项目里有我不知道的T0约定\n"
  "需要你侧的数据: T0里对未涨停层的原始定义\n"
  "待裁决: 无"
))

# 封顶到点或僵持 → 分歧报告给用户，不伪造共识
```

反模式：
- 让网页端先看你写好的答案再「评审」——那只是带步骤的同意
- 对方两轮全同意就当收敛——谄媚不是共识
- 打到轮次上限继续磨——出分歧报告，让用户裁
